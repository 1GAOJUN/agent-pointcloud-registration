## 2. Most-likely root cause

The formal Evidence tree for a run is a **fixed 8-slab layout**
(`00_INDEX / 01_AGH / 02_AGENT / 03_TOOL_CHAIN / 04_CONFIG / 05_VALIDATION / 06_VISUALS / attempts`)
that the B3A/B3B evidence tooling creates *inside a run directory* via `mkdir -p`.
If the run-directory variable used by that tooling resolved to the repository root
(e.g. a relative path bug, or a `run_dir` that was computed before the
`outputs/submission_evidence/B3/L1/runs/<run_id>` component was appended), the
entire 8-slab skeleton lands at repo root instead of inside the run.

> **MOST_LIKELY**: incorrect relative Evidence path during earlier B3A run setup.
> A run-skeleton creation step executed with its target directory resolving to the
> repository root, producing the 8-slab layout (`00_INDEX…06_VISUALS`, `attempts`)
> plus a stray `<run_id>` directory (`b3_l1_20261007_seed101_blind01`) and a stray
> `L1/runs` fragment — all at repo root.

This is an *inference*, not a confirmed fact: the actual tool call that created
these directories was never captured in evidence, and the directories themselves
are empty, so the exact script line cannot be read back. Recorded as
**MOST_LIKELY** per H1 rule (do not fabricate a definitive root cause).
