#### 阶段1：AGH 源码环境搭建与启动
**核心目标**：从源码构建可运行的Agnes Harness本地服务，完成基础交互验证
**前置软件准备**：
- Node.js 24 LTS（官方要求最低版本，用于原生模块构建）
- Git（代码仓库克隆）
- Visual Studio Build Tools 2022（Windows平台C++编译工具链）
- Node.js 24 对应开发SDK（头文件 + node.lib，原生编译必需）

**标准步骤**：
1. 安装基础软件
   - 安装Node.js 24 LTS，命令行执行`node -v`确认版本为v24.x
   - 安装Git，配置网络代理保证GitHub访问通畅
   - 安装VS Build Tools 2022，勾选「C++生成工具」核心组件

2. 配置Node原生编译依赖
   - 下载与Node 24版本匹配的头文件包与`node.lib`
   - 新建专用目录存放SDK，配置系统环境变量`AGNES_NODE_HEADERS`指向该目录

3. 仓库克隆与构建
   ```bash
   git clone [AGH仓库地址]
   cd agnes-harness
   # 执行源码构建脚本，完成Node原生模块编译
   ```

4. 服务启动与链路验证
   - 启动AGH本地服务，浏览器访问管理面板地址`xxx.xxx.xxxx`
   - 发送测试指令「你是什么模型」，收到`Agnes-3.0-flash`正常回复，确认全链路打通

**阶段产出**：可用的AGH本地Agent服务，对应造轮子任务5验收通过。

### 二、今日遇到的所有坑与解决方案
#### 1. Node 环境类坑
| 坑描述 | 根因 | 解决方案 |
|--------|------|----------|
| Node版本反向降级 | 误将Node从24降级到20，低于官方最低要求，原生模块编译不兼容 | 卸载旧版本，重装Node.js 24 LTS，严格对齐官方版本基线 |
| 缺少Node开发SDK | 常规安装的Node仅含运行时，缺失编译原生模块所需的头文件和导入库，构建报`Node headers/library missing` | 单独下载对应版本的头文件包与`node.lib`，配置`AGNES_NODE_HEADERS`系统环境变量 |

#### 2. 编译工具类坑
| 坑描述 | 根因 | 解决方案 |
|--------|------|----------|
| VS Build Tools安装路径冲突 | 产品路径、下载缓存、共享SDK路径设为同一文件夹，系统禁止路径重叠 | 将三类路径分别设置为独立文件夹，完成C++工具链安装 |

#### 3. 代码仓库类坑
| 坑描述 | 根因 | 解决方案 |
|--------|------|----------|
| GitHub克隆网络不稳定 | 国内直连GitHub速度慢、易断流，易导致仓库文件隐性残缺 | 配置Git走本地代理加速克隆，保证文件完整 |
| 构建脚本后缀不匹配 | 仓库构建脚本已升级为`.mjs`（ES模块格式），上层调用仍写死旧的`.js`后缀，持续报模块不存在 | 定位后缀差异，复制原文件改为`.js`后缀，兼容原有调用路径 |

#### 4. Agent 执行类坑
| 坑描述 | 根因 | 解决方案 |
|--------|------|----------|
| Agent内运行脚本无输出 | Python标准输出存在行缓冲，非交互式子进程中输出未实时刷新，Agent捕获不到 | 本地手动运行脚本验证，结果效力完全一致；后续可改为强制写日志的方式优化 |

#### 5. 诊断偏差类坑
| 坑描述 | 根因 | 解决方案 |
|--------|------|----------|
| 初期误判报错根因 | 遇到构建失败时先入为主判定为C++工具缺失，漏判了更前置的Node头文件问题 | 结合最内层报错关键字逐层定位，按「头文件→编译工具→代码」的顺序排查 |
